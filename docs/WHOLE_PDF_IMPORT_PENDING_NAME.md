# Whole-PDF Import with a pending target name

This advances Milestone 1 / HIST-4 / DATA-1 / UI-10 / SEC-2. The separately
invoked PDF Import composition exposes `enablePendingRenames()`. It enables the
matching private session-binding mode. Construction keeps this mode off;
production editor callers and ResourceLoader registration remain inactive.

## Preserve both identities

An editor can rename an existing whole-PDF layer set before saving it. The
catalog still discovers sources by the exact saved target name. The approved
dialog presents the current target name and keeps its existing decisions,
wording and controls.

Preparation captures the actual saved base, complete live work and participants.
In the explicit mode, it verifies a coherent complete-group name, valid spelling
and stable stored membership. A detached planning copy projects only the target
group's labels back to the saved name. The unchanged native Source and detached
Import Planner then perform their existing strict owner, file, member, source
pin, page and admission checks. Their read evidence stays unchanged.

Only after planning succeeds does the binding apply the captured pending name to
the detached candidate. The actual live snapshot remains the before-side
authority. Native blank surfaces and admission origins keep their native names,
IDs and exact captured contents. Source citations retain their actual owner,
revision and source anchor. No source is renamed, saved or acknowledged by
preparation. Append, Replace and initially empty targets follow existing rules.

## History and drafts

Whole-group Undo/Redo preserves the pending target name and restores the Import
content delta. Page turns, complete drafts, reconciliation and successful Save
use the existing application transaction and private source claims. Save records
the current name in the owning page revision; refusal retains complete work.

The inert draft validator identifies saved and live target groups by their
stable member IDs and fixed fields. Each live holder has one coherent valid
name; unrelated file/slide/set content remains exact. Native temporary and
admission pairs stay byte-for-byte equal even when their original name differs
from the pending name. The controller checks the envelope's name against the
validated target anchor when the active page is a native blank.

Draft validation grants no authority. Recovery still performs the unchanged
fresh native source, target, current/historical origin and complete-work checks.
A fabricated native origin name cannot become valid by matching a live name or
by appearing in a serialized draft. Restore remains explicit; backups remain
intact on cancellation or refusal.

## Refusal and remaining acceptance

Partial renames, invalid names, changed or missing stored members, changed pins,
duplicate pages, ambiguous same-file groups, changed native reads and stale
participants refuse before applying Import. Mode changes across a captured read
also refuse. The original binding mode and standalone Source/Planner retain
their pending-name refusal. Existing image/slide Import stays unchanged.

This client qualification does not activate the feature or establish native
HTTP/browser, supported-version/mobile, upgrade or owner acceptance. Creation of
a completely absent target PDF group remains separate work before activation.
