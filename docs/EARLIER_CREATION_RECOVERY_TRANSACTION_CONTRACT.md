# Earlier creation recovery transaction

This inactive path restores verified image/slide creation backups into an exact
current native admission. It advances page ownership, native history and safe
recovery. Existing callers, prompts and exact-base recovery remain unchanged.
No Save is automatic; source backup bytes and writer destinations stay intact.

## Private preparation

The controller first obtains a genuine earlier-creation inspection certificate.
The bridge checks its native current target against this session and requires
the complete historical identity, a version-two working-copy backup, and an
unsaved history marker. Whole-PDF backups, unsupported first-Save rename and
insufficient or inconsistent data refuse without changing current work.

Only the working-copy identity, each checkpoint's internal surface ID and each
explicit citation's target surface ID are remapped. A citation must belong to
the admitted original member before remapping. Layer IDs, groups, reading
order, unknown fields, nulls, canvas values and source identities are preserved.
Local names, arbitrary text matches and caller-supplied IDs grant no authority.

Existing private recovery preparation builds current-identity session
checkpoints, display, selection and Undo/Redo associations. Preparing or
releasing a plan changes no live model or backup. Pending edits retain the
existing recovered-step behavior. Saving/conflict/uncertain backups retain
their publication hold; a historical backup cannot claim it was saved.

## Revalidation and commit

Every retained Import citation is revalidated, including citations reachable
only through Undo or Redo. The existing history transaction deduplicates source
reads and checks each complete current admission. The complete historical and
current native proof is repeated as the final read. Full editor/session/history,
configuration, selection, methods, locks, queues and backup guards run across
each await and again immediately before commit.

After all checks pass, session, display, selection and history commit
synchronously. Rendering notifications follow the model commit and report
diagnostics. No recovery source is retired or overwritten. The shared recovery
record excludes competing legacy commit/release while validation is pending.
Refusal preserves newer work and closes the private plan. Explicit later Save
uses the unchanged native first-Save source/admission and publication guards.

## Qualification boundary

The entry points have no active UI caller. Controlled client/model qualification
does not establish native HTTP/browser/mobile/1.44 or owner acceptance. A
charter-approved behaviour brief and screen review are required before changing
the visible recovery flow. Whole-PDF Import, owner renames, first-Save rename,
older insufficient backups and broader migration/upgrade acceptance remain
separate. This code checkpoint does not complete the page-history milestone.
